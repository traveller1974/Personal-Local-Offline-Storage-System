# 识图辅助填单架构与 6.1-sol 执行结果

识别负责提出填写建议，入库采用最终表单。识别没有看清数量列、照片合计有误、原单位不明，都会给出提示；用户可以在同一页面补齐、修改并加入清单。整数数量、有效货品、库存范围和最终入库确认继续由业务层检查。

## 调用与结果

- 千问使用 DashScope 原生 `qwen3.5-ocr`，只设置用户提示，不设置自定义 system 消息。
- DeepSeek 使用官方 `https://api.deepseek.com/chat/completions` 和 `deepseek-flash`。原请求中的 `deepseek-v4-flash-vision-exp` 是旧别名，官方当前模型为 Flash。采用图像输入和 JSON 输出，本机仍逐项校验。
- 缺失数量留空，禁止填零掩盖缺失，禁止沿用过去单据数量。保留所取数量列的原文和其他数量列候选。
- 行标识与照片行序分开保存；重复货品、不同分区重号和零数量行保留。
- 默认一次请求。主程序仅在有相关、已人工确认的例子且有未解决字段时再发一次补充请求；总等待预算180秒，单次90秒。第二次结果行数、行序或原始名称和数量不一致时保留首轮结果。
- DeepSeek 长单据同时发送整单和至多8张自上而下的细节图，全部来自已确认的截图。交界保留少量重叠，由模型依据照片位置处理；本机禁止按货品名称去重。这仍需真实长单据验收。千问维持单图输入，以免引入未经验证的多图调用方式。
- 鉴权、欠费、取消和超时均不启动切换模型的重试链。原有填写内容保留；迟到响应不覆盖人工填写。

## 货品匹配

1. 类型、名称、规格、颜色、编码完整且唯一匹配时选定已有货品。
2. 编码在全部启用货品中唯一，且识别出的其他字段没有冲突时，补齐缺失资料。
3. 同一单据样式的已确认修正，第一次成为候选；经过两张不同、有效的已入库单据确认，且没有不同货品的冲突时，允许自动匹配。
4. 关键词或模糊候选只供选择。多个规格、颜色或编码冲突时必须选择货品。

“已自动填写”仅用于数量列明确、单位一致、没有识别问题且货品唯一的行。其他行显示待补齐的字段或对照提示。名称、规格、颜色保留现有关键词词条功能。用户可新建货品、补充漏行和移除多余行。

## 纠错记忆

业务数据库仍为 schema v2；另设 `Data/recognition-memory.db`（schema v1）。记录包括原始字段、最终入库行、关联货品、样式、人工确认状态、启用状态和来源。表单字段分别记录来自识别、已有货品或人工填写。

主程序加入清单时保存原始证据；最后确认入库时，重新根据当前清单生成反馈记录。库存事务成功后，才从已保存的单据和照片记录写入纠错数据库。写入记忆失败不会把成功的入库改成失败；启动或设置中的“补记已入库的修正”可幂等补记。取消窗口或入库事务失败不会留下学习记录。

自动生成的资料不作为人工标准。选择货品、手工修改货品资料或勾选“已核对”才可确认货品关联；仅修改数量不会把自动选定的货品升级成学习标准。数量只记录本次结果，不用于填下一张单据。

检索最多3条相关货品修正；没有相关例子就不发送。货品被停用、资料已改变、来源单据被作废或清理时，不再使用该记忆。设置可关闭学习、停用单条记录，或导出核对参考给独立程序。备份包含记忆数据库；旧备份没有该文件仍可恢复。云模型权重不会在本机被训练。

## 真实验收与默认模型

软件测试与真实识别准确度分开记录。现有人工基准包含两张单据21行，其中39个名称、规格、颜色字段缺少可靠答案。这些字段不计为正确，也不从模型输出补作标准答案。

上线通用自动填写前，应扩充至20张不同货单、200行，并保留完全未用于纠错例子的新单据。检查漏行、错货品、错数量、需要改的字段数、核对耗时和调用用量。自动采用的行不能存在未提示的错误或漏行。

默认保留千问。只有千问不通过、DeepSeek真实测试通过时才切换默认；两者都通过时优先需要修改更少的模型，持平保留千问。没有通过的场景继续显示建议供人工填写。
