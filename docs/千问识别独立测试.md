# 图像识别独立测试（千问与 DeepSeek）

双击 `Stock.RecognitionLab.exe` 即可使用，不需要安装 .NET、Python 或库存软件。程序不连接库存数据库，不保存密钥。新版升级包内置同一份经过软件验证的EXE，用户按原进货流程操作；真实识别准确度见《验收报告》，尚未达到通用自动填单标准。

## 测试步骤

1. 选择千问或 DeepSeek，填写对应API Key和官方服务地址。千问固定使用 `qwen3.5-ocr`；DeepSeek 使用官方 `deepseek-flash`。密钥仅在本次窗口会话使用，不读取主程序设置。
2. 选择对应样单，或选图、拖入JPG/PNG。人工基准有17行和4行两个样单；原图片由用户在本机选择。
3. 框选表格并应用裁剪。保留表头、全部货品和分区合计，检查显示截图后勾选允许上传。
4. 点击“识别确认的截图”。单次点击最多一个请求，90秒超时，可取消。DeepSeek 对较大的表格和长图，在同一次请求内附带最多8张重叠分段图，仅从确认后的截图裁出。
5. 图片占约40%，结果占约60%。右侧显示全部14个行级字段、数量列状态、分区合计、计算合计、警告、耗时和Token。长字段换行，全部结果可纵向滚动。
6. 在“原始输出”查看服务响应、模型原文和解析结果；解析失败时也保留已收到的响应供检查。
7. 在“样单对比与意见”检查漏行、数量、货品和原始字段，记录意见并导出。

关闭窗口后密钥不保存。主程序使用的密钥应在“设置与备份”中保存，由Windows加密；两者配置相互独立。

## 比较模型与核对参考

分别选择千问和DeepSeek并填写各自配置后，点击“比较两种模型”。同一截图依次发送到两个服务，每个最多一次请求，总等待预算180秒；取消、鉴权或超时后停止。导出的 `model-comparison.json` 保存已完成的模型响应、解析结果和诊断，部分失败时不表示两种都完成。

主程序可导出“核对参考”JSON；独立程序点击“载入核对参考”并勾选“参考核对记录”后，最多使用3条相关记录。相关性依据当前截图此前识别的货品名称，不使用人工基准答案。首次没有相关识别结果时不发送参考。验收新货单时关闭参考，分别检查有参考和无参考的效果。

参考不包含历史数量，不改变云模型权重。主程序保存真实修改是在最终入库后，独立程序只记录测试意见。

## 对比和导出

人工基准来自 `docs/样单人工基准.json`。`null`表示尚未辨清的字段，不算正确，也不能以模型答案补作标准。字段正确率只统计已确定的名称、规格、颜色、编码和标识，不等于整张单据准确率。行数、类型、数量、单位和合计另行检查。

导出时创建 `run-时间-编号` 目录，包含实际上传截图及哈希、EXE版本与哈希、`run.json`、服务响应、模型原文、有效解析结果、对比报告和人工意见。模型比较另有 `model-comparison.json`。不导出密钥、鉴权头或图片Base64，但截图和识别文字仍在本地导出目录中。

推荐保存在项目 `artifacts/recognition-lab/runs`，该目录被Git忽略。“载入本地响应”可回放服务响应、模型JSON或导出结果，不联网；导出明确标记回放，不能代替真实验收。

## 构建和接入

```powershell
.\scripts\build_recognition_lab.ps1 -SmokeTest
.\scripts\verify_recognition_integration.ps1
.\scripts\build.ps1 -SkipOcrBuild -UseEmbeddedRecognition -AppVersion 1.2.1
```

模块方向为 `Stock.RecognitionLab → Stock.Recognition`；识别库不依赖库存或WPF。主程序原有入口通过适配层复用同一解析器和服务实现。后台协议v2通过UTF-8管道传递截图路径和配置，密钥不写到命令行或缓存。

启用构建使用 `dist/Stock.RecognitionLab.exe`，不在主程序打包时重建，校验SHA-256和接入流程。隐藏后台在主程序内按哈希提取和缓存；只有本地提取失败且尚未请求时可退回进程内实现，请求开始后不再次调用另一后台。

识别实现或提示词变化后需要重新验收真实样单。通过验收后，由开发者生成启用该版本的升级安装包；用户关闭软件、安装升级，继续“照片识别进货 → 填写清单 → 确认入库”，无需复制识图文件。测试窗口的“本次结果已人工核对通过”只保存意见，不自动安装或切换主程序。

本版保留原1.1.4识图EXE和安装包供比对与回退。新版通过软件功能测试。两张固定照片的DeepSeek测试完整返回21行，数量全部匹配人工基准，仍有编码、颜色和类型错误。千问和DeepSeek均未通过全自动填单验收，详见《验收报告》。
