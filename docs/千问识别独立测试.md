# 千问图像识别独立测试

交付独立识别库和单文件桌面测试 EXE。库存主程序保留原识别实现，同时把同一识图 EXE 内置为备用的新后台；默认仍使用原实现。用户确认真实样单测试通过后，由开发者生成启用新后台的升级安装包。

2026-10-07更新：用户已确认模块可用，1.1.3交付升级包启用这份已确认的EXE，并加入名称、规格、颜色的本地词条搜索。下文的默认开关指源码构建默认值；用户使用1.1.3启用版时无需切换后台。

主进货弹窗已调整为左侧图片约40%、右侧结果约60%，补齐全部12个行级字段、实发列状态、分区合计和警告。此源码调整不代表已经更新本机已安装的软件。

## 启动与真实样单测试

双击 `dist/Stock.RecognitionLab.exe`，或在项目目录运行：

```powershell
.\scripts\start_recognition_lab.ps1
```

默认发布为包含 .NET 10 Windows x64 运行时的单个 EXE，使用时不需要安装 .NET、Python 或库存软件。移动或交付时只需复制这一份 EXE。人工样单基准也内置在 EXE 中，原始样单照片仍由用户在本机选择。

1. 在“千问连接配置”填写 API Key、所属地域的原生 DashScope 地址及必要的业务空间。密钥仅保留在本次会话，不读取库存软件已保存的设置。
2. 选择 `sample-1（17行）` 或 `sample-2（4行）`，点击“打开选中样单”。基准中的图片位于 `D:\识别用图像`；也可选图或拖入 JPG/PNG。自选图片不自动套用样单答案。
3. 框选表格，预览并应用裁剪。截图须保留列标题、全部货品和分区合计。可旋转、缩放或恢复原图；图片编辑后需要重新确认上传范围。
4. 勾选上传确认，再点击“识别确认的截图”。每次最多发送一次请求，没有自动重试，可取消。
5. 左侧约40%显示实际上传图片，右侧约60%展示结果。右侧包含全部12个行级字段、实发列状态、分区合计、明细计算合计、警告、耗时及 Token 用量。长规格换行，多行结果纵向滚动。
6. 在“原始输出”分别查看模型原文、完整服务响应及解析结果。即使结构校验失败，已经收到的原始响应仍可查看、导出。
7. 在“样单对比与意见”检查原行序、实发数量、类型、原单位、物料编码、标识、名称、完整规格和颜色；记录人工核对意见，然后导出。

开始识别后连接配置自动收起，留出更多结果空间。再次测试前可展开修改。关闭窗口不会保存密钥。

## 对比与导出

人工基准来自 `docs/样单人工基准.json`，不是模型输出。基准中的 `null` 表示待人工确认，不能算正确，不能以模型答案补作标准。字段正确率只统计已确定的名称、规格、颜色、编码和标识；它不等于整张单据准确率。

对比同时显示“人工基准、模型原值、解析结果”，并单独记录本地解析产生的变化。模型分区合计与明细计算合计分别比较；无效数量或未知类型不能被静默略过而产生看似正确的合计。行数和实发列状态需要单独核对。

每次导出在选定父目录下创建独立的 `run-时间-编号` 目录：

- `uploaded-image.png/jpg`：本次请求使用的准确截图，导出时校验 SHA-256。
- `run.json`：测试 EXE 版本与 SHA-256、调用来源、图片哈希与尺寸、操作记录、诊断、解析结果、对比及人工意见。EXE 哈希用于确保升级包内置的正是本次测试版本。
- `response.txt`、`model-output.txt`：服务响应及模型原文；调用或解析失败时仍保留可用内容。
- `recognition.json`、`comparison.json`：有有效结果或选定基准时生成。
- `report.md`、`review.txt`：便于审查的报告与人工意见。

默认推荐将测试证据保存到项目的 `artifacts/recognition-lab/runs` 中，此目录被 Git 忽略。记录不包含请求鉴权头、配置密钥或请求图片的 Base64。截图和识别文字留在用户选定的本地导出目录。

“载入本地响应”可打开原生服务响应、模型 JSON 或本程序的 `run.json`，方便重复检查解析和界面。它不联网，导出会标记 `local-replay`、`realCallEvidence=false`。本地回放和模拟测试不能代替真实调用验收。收到真实 HTTP 响应也不等于识别准确率已通过；还需核对有效结果。

也可使用现有 Python 评估工具读取新导出：

```powershell
python scripts/evaluate_samples.py --sample sample-1 --result <导出目录/run.json> --output <对比报告.json>
```

## 构建与隔离验证

```powershell
.\scripts\build_recognition_lab.ps1 -SmokeTest
.\scripts\verify_recognition_integration.ps1
python -m unittest discover -s tests -p test_evaluate_samples.py
```

独立构建脚本只恢复识别库测试和 WPF 测试程序的依赖，不需要旧项目的 OCR、OpenCV 或 NSIS 工具。单文件发布在 `artifacts/recognition-lab/single-file`，交付文件复制到 `dist`。离线检查把这一份 EXE 单独复制到无 DLL、无基准 JSON 的目录再启动，包含真实后台子进程的通信、错误、取消和超时检查。`-FrameworkDependent` 仅供开发者发布依赖已安装 .NET 10 Windows Desktop Runtime 的版本；普通用户使用默认自包含版本。

模块引用方向：`Stock.RecognitionLab → Stock.Recognition`。识别库使用自身的货品类型、结果和异常，没有 SQLite、库存服务或 WPF 依赖。主程序通过适配层转换原接口的类型和异常，原模块的请求、解析及测试继续保留。

`verify_recognition_integration.ps1` 分别生成默认旧后台和启用新后台的隔离发布目录，验证主程序内置资源、哈希校验、全部字段、原行序、重复货品、零数量及核对后加入清单和确认入库的完整流程。这里只使用项目内的合成图片、模拟响应与测试数据库；不需要恢复旧 OCR 工作程序或 NSIS，不生成安装包，也不运行真实用户数据入口。

离线桌面检查只使用合成图片和模拟服务，覆盖裁剪预览、旋转、恢复、上传字节、全部字段、比例布局、失败诊断、导出、忙碌状态、取消与迟到响应。缩放检查使用 WPF 布局变换模拟100%／125%／150%；实际显示器 DPI 和人工操作仍需用户检查。

## 用户确认后如何启用

两张真实样单及用户补充样本需逐行核对，人工基准未确定的字段需单独确认。错误修正后重测受影响样本。用户审查导出证据并明确确认通过后，开发者使用被确认的同一份 EXE 生成启用新后台的升级安装包，并完成安装升级回归。

用户只需关闭主程序、运行升级安装包，再正常打开软件。操作仍是“进货 → 照片识别 → 逐行核对 → 加入进货清单 → 确认入库”。无需手工复制识图文件、启动测试窗口、切换界面或重新填写已有百炼设置。安装程序继续保留数据库、照片、加密设置和备份。

技术上，测试 EXE 有普通窗口与隐藏后台两种入口。升级后的主程序在用户主动识别时，从自身程序集内提取 EXE，按 SHA-256 缓存并核验，通过 UTF-8 管道发送截图路径和当前配置，接收结果后进入原核对界面。密钥不写入命令行、缓存文件或输出。仅在模块本地提取失败且尚未开始请求时使用原实现；新后台开始请求后发生错误不会自动改用原实现再次调用。

开发者构建开关默认为 `UseEmbeddedRecognition=false`。确认后生成启用版的命令为：

```powershell
.\scripts\build.ps1 -Bootstrap -UseEmbeddedRecognition -AppVersion 1.1.3
```

启用版直接内置 `dist/Stock.RecognitionLab.exe`，不会重新构建这份已确认的测试模块，并在生成安装包前验证内置文件的哈希和完整接入流程。若更改识别库、提示词或重新生成测试 EXE，应先重新测试对应样本。普通 `build.ps1` 会构建并内置新模块，但默认仍选择旧后台。旧1.1.2安装包不被此构建覆盖。

测试窗口内选择“本次结果已人工核对通过”只记录该次核对意见，不会自动安装、更新或切换库存程序。
